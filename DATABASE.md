# Database Reference

## Tables

| Table | Purpose |
|---|---|
| `certificates` | Publicly verifiable certificate records. |
| `admins` | Email and server-side password hashes for administrators. |
| `admin_sessions` | Hashed opaque session tokens with expiration. |

`certificates.code` is a unique `CHAR(9)` constrained by `^[0-9]{9}$`. `status` is constrained to `valid`, `expired`, or `revoked`. Dates use PostgreSQL `DATE` and may be null where the UI permits. Timestamps are generated by PostgreSQL. An update trigger refreshes `updated_at`.

## Installation and seed

Apply the complete idempotent script:

```bash
psql "$DATABASE_URL" -f database/schema.sql
```

The seed uses `ON CONFLICT (code) DO UPDATE`, so repeated runs do not create duplicate records. It preserves the required test certificate:

## Security notes

Only the Worker has `DATABASE_URL`. All queries use parameter placeholders for user values. Public verification selects only the requested code and the public certificate fields. Admin session tokens are stored as SHA-256 digests; passwords are PBKDF2-SHA-256 hashes with a unique salt and 210,000 iterations.

## Schema changes

For a future migration, add a numbered SQL file, apply it against Neon, and keep it safe to re-run with `IF NOT EXISTS`, `CREATE OR REPLACE`, or guarded updates. Test the Worker after every schema change.
